## Methodology

- Host: 4 x arm64 CPU (implementer 0x61, part 0x000), MemTotal 6041448 kB, kernel 7.3.0-9-generic arm64, page size 4096, Firecracker v1.18.0.
- Cold cache: before every cold sample the bench runs the equivalent of `sync && echo 3 > /proc/sys/vm/drop_caches` (sync(2), then writes 3 to /proc/sys/vm/drop_caches). A warm sample repeats the same mode immediately, without dropping.
- Iterations: 10 per mode and cache condition in the boot and pager tables; density: 1 iteration per clone count (--fast); restores staggered 3 in flight, since the table measures steady-state RAM and N simultaneous cold restores stall a small host. Every density sample is cold, so golden mem file pages are charged to the live branch cgroups that read them instead of to an earlier, deleted cgroup.
- Restore ms: from the Firecracker API socket accepting connections to the guest agent answering /health with ok (cold boot: ok and pg_ready).
- First query ms: from just before pager setup and the snapshot load call (cold boot: from the API socket) to the first successful `pg_isready` inside the guest through the agent. The probe retries every 500 ms while Postgres refuses connections. Pager setup (fadvise calls, uffd socket and mmap) is inside this window.
- Total ms: the whole sample from netns creation to every branch serving, including cgroup, reflink clone, gateway, and firecracker start; for run-3-branches also the workspace pack and sync.
- Host RAM: `memory.current` of each branch cgroup. A page cache page of the shared golden mem file is charged once, to the first cgroup that read it, so the sum counts shared pages once and private copy-on-write pages per branch.
- Working set: re-recorded before the pager table. Caches dropped, one File restore served its first query, then mincore(2) over the mem file: 101264 of 262144 pages, 395 MiB of 1024 MiB. `init` also records ws.bin right after writing the snapshot, but freshly written pages are all cached, so that copy covers nearly the whole file.
- Teardown: after every sample the bench removes every branch resource and scans for leftover netns, veths, cgroups, clone dirs, firecracker processes, and listening gateways. Any leftover aborts the bench.

## Reading the numbers

A snapshot restore reached a serving guest in 190 ms median with cold caches and 166 ms warm, against 6234 ms for a cold boot of the same rootfs (32.7x). End to end, with netns, cgroup, reflink clone, gateway, and firecracker start, one cold branch took 1848 ms. Three branches with a workspace sync were all ready in 12266 ms cold and 11988 ms warm. At 10 clones the branch cgroups held 620 MiB in total, 62.0 MiB per clone, where private copies of guest memory would take 10240 MiB.

With cold caches the first query returned after 1601 ms on mmap, 1546 ms on fadvise (395.6 MiB advised), and 1111 ms on uffd (7632 faults, 29.8 MiB copied); uffd was fastest. With a warm page cache: 1473 ms mmap, 1494 ms fadvise, 953 ms uffd. Prefaulting the recorded working set cut the cold first query by 55 ms against plain mmap. UFFD did not lose to mmap on a warm cache in this run (953 vs 1473 ms).
